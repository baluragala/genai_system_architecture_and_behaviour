The two boundaries teams think they have

Where incidents actually come from

L4 / L6

“The model decides.”

No. The model proposes. If your code takes the model’s word for the final state of the world, you have no L6 — whatever your diagram says.

The difference between a system whose worst case is bounded by your rules, and one bounded by the model’s worst day.

L3 / L5

“Just put the data in the prompt.”

Facts enter through L5 and get cited.
Instructions enter through L3 and get tiered.

Mix them and you cannot answer “where did this fact come from?” — and a claimant can reprogram you with a polite paragraph.

The prompt makes the right behaviour likely.
The guardrail makes the wrong behaviour impossible.

Block 2 · 20 min

The vending machine and the consultant

Traditional ML is a vending machine. Fixed slots. Press B4, get B4. A thousand times. When it’s wrong it’s wrong consistently — which makes it debuggable.

An LLM is a consultant. Ask tomorrow, phrased slightly differently, get a different answer. Possibly a better one. Both defensible. Nobody thinks the consultant is broken.

You cannot test a consultant by pressing buttons and checking slots.

Almost every “GenAI is unreliable” complaint is vending-machine test methodology applied to a consultant.

Six things changed

And one of them is dangerous

Traditional MLGenAI system
Outputa label from a fixed setopen-ended text
Determinismsame in → same outsame in → a distribution
Shapefixed pipeline you wrotedecided at runtime by the model
Cost / latencyknown before you rununknown until it finishes
Correctnessmeasurable against labelsoften a judgement call
Failureconfidently wrong and looks wrong confidently wrong and looks right

A broken classifier returns 0.97 for a truck and your monitoring catches it. A broken LLM returns a beautiful paragraph wrong in one clause, and your monitoring catches nothing.

Temperature 0 is not a determinism guarantee.
It is a greedy decoding strategy.

Why orchestration, specifically

The step count is decided at runtime

traditional :  features → model.predict() → post-process → done

GenAI       :  prompt → model → "call lookup_policy" → run it → feed back
                     → model → "call compute_payout" → run it → feed back
                     → model → answer → validate → maybe reject → maybe retry
Because…You need…Which lives in
cost and latency are unknown in advancebudgetsL2
the model may never decide it’s finishedtermination conditionsL2
any step can failretries that don’t loop foreverL2
the output is a proposalvalidation as a pipeline stageL6
you can’t reproduce from the input alonetracesL7
If a correct answer exists, compute it.
If judgement is required, generate it — then constrain it.

Block 3 · 30 min · the block that changes Monday

Four questions a string cannot answer

  1. Who is allowed to change the rule about settlement figures?
  2. When compliance and the adjuster conflict, which wins?
  3. The claimant’s own words are in the prompt. Are they instructions?
  4. We shipped a prompt change on Friday. What changed, and who approved it?

None is answerable about a string. All four are trivial about a hierarchy with precedence and provenance.

Prompting is not copywriting.
It is an architectural layer with an access-control model.

Four tiers and a quarantine

The chain of authority

   Regulation            IRDAI says it. Nobody in the building may override it.
     > Company policy    Compliance owns it. Changing it is a release, not an edit.
       > Operating brief The workflow author sets it, for this task.
         > Session       The adjuster’s preference, for this one case.

   …and the customer’s letter is EVIDENCE. Not an instruction.
TierWho may change itExample
T0 RegulatoryNobody“Never imply a settlement is guaranteed”
T1 OrganizationalCompliance, at release“Auto-approval ceiling is ₹50,000”
T2 OperationalThe workflow author“Motor own-damage claims only”
T3 SessionThe adjuster, per run“Explain simply; claimant is elderly”
UNTRUSTEDclaimant text, OCR, docs, tool results Fenced. Never instructions.

The tier is decided by where the content entered the system — not by how senior the author sounds.

The live demo

One line, and the attack succeeds

A claimant writes a perfectly ordinary, slightly pushy paragraph. No “ignore previous instructions”. Nothing a regex catches.

hierarchy.quarantine_untrusted = False     # ← the only change

Same model. Same tools. Same rules, word for word, still in the prompt. The injection now succeeds.

The model did not fall for anything.
It was handed a document in which the ceiling had been lifted —
and it read that document correctly.

The vulnerability was in the assembly, not the model.

You cannot regex your way out of prompt injection. Blocklists enumerate the attacks you thought of; the attacker’s whole job is thinking of one you didn’t. Structural quarantine is the parameterised-SQL move — make data structurally incapable of becoming code.

Block 4 · 20 min

Multimodality is a multiplier

It does not add one failure mode. It adds one at every layer you already had:

L1a 12 MB photo, sideways, with EXIF rotation nobody applied
L3three images and two documents — in what order, with what labels?
L4it cannot read the smudged digit, and does not mention this
L5the OCR tool and the vision model disagree about the total
L6how do you write a contract test for “actually looked at the photo”?
L7your audit log now contains photographs of people’s vehicles

Plus one genuinely new class: cross-modal contradiction. The text says front-right. The photo shows rear-left. Neither source is malfunctioning.

A photograph is a second witness, not a judge.

Six perceptual failure modes

And the control for each

ModeExampleControl
Resolution lossIs that ₹79,886 or ₹19,886? Ask for legibility as a separate field
AmbiguityA tick between two boxes Make "ambiguous" an allowed answer
Cross-modal contradictionText says front; photo shows rear Extract per-source first, reconcile second
Spatial reasoning“Which side is damaged?” Anchor to landmarks that don’t flip
OCR confusion1/7, 0/O, 1,94,000 vs 194,000 Never let vision be the sole source of a number
Confident hallucinationA plate number in a photo with no plate Require a grounding phrase per assertion
A contract with no escape hatch forces a guess.

Block 5 · 25 min

The kettle doesn’t know where the electricity came from

Coal plant, solar farm, or a diesel generator in the basement. Your kettle knows 230V, 50Hz and a plug shape. That ignorance is the entire value.

   without a protocol :  N apps × M tools     =  N × M integrations
   with a protocol    :  N clients + M servers =  N + M

3 apps × 4 tools = 12. Or 3 + 4 = 7. Add a fifth tool and watch the gap widen.

A protocol solves plumbing.
It never solves meaning.

Change a tool’s semantics — fraud bands from LOW/MEDIUM/HIGH to a 1–5 scale — and every consumer breaks regardless. That needs versioning.

The honest accounting

What a protocol costs

You gainYou pay
Discovery — clients learn tools at runtimeSerialisation on every call
Versioning — server evolves without client redeploysA process to supervise and monitor
Isolation — a tool crash doesn’t take the app downA new failure surface
Authority — the server decides what it exposesHarder local debugging
Reuse — one server, many clientsLatency — measurable

Use it when: another team owns the tool · the tool outlives the app · several apps need it · it needs its own release cadence.
Don’t when: it’s three functions in one codebase with one consumer.

Knowing which situation you are in
is the actual architectural skill.
